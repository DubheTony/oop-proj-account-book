面向对象多态

12处应用 ▼
动态分派运行时根据对象真实类型决定执行哪个方法
Controller通过set_diagnosis_strategy()注入策略后，调用diagnose()时Python在运行时查找对象实际类型的方法——这是动态分派的核心。同一行代码，注入不同策略就执行不同算法。
services/finance_controller.py:227-256
# 注入策略 controller.set_diagnosis_strategy(SavingRateStrategy()) # 动态分派到 SavingRateStrategy.diagnose() report = controller.diagnosis_strategy.diagnose(txns, budgets) # 切换策略 controller.set_diagnosis_strategy(CategoryOverrunStrategy()) # 此时动态分派到 CategoryOverrunStrategy.diagnose() report = controller.diagnosis_strategy.diagnose(txns, budgets)
ABC抽象基类（ABC + @abstractmethod）
项目中三个策略族（DiagnosticStrategy、BudgetRule、SavingsMethod）全部使用ABC作为抽象基类，用@abstractmethod装饰抽象方法。子类若不实现抽象方法则无法实例化。
strategies/diagnostic_strategy.py:8-18 · rules/budget_rule.py:6-12 · methods/savings_method.py:8-13
from abc import ABC, abstractmethod class DiagnosticStrategy(ABC): @abstractmethod def diagnose(self, transactions, budgets) -> DiagnosisReport: ... class BudgetRule(ABC): @abstractmethod def allocate(self, income, history) -> dict[str, float]: ... class SavingsMethod(ABC): @abstractmethod def calculate(self, monthly_income, history) -> SavingsPlan: ...
策略模式策略模式——三个完整的策略族
项目在诊断、预算、储蓄三个模块均应用策略模式。每个模块定义一个ABC接口+多个具体实现。Controller持有接口引用，运行时注入具体策略。新增策略不影响现有代码（开闭原则）。
全部strategies/ · rules/ · methods/ 目录
# 诊断族: DiagnosticStrategy → SavingRateStrategy / CategoryOverrunStrategy / ConsumptionStructureStrategy / CompositeDiagnosis # 预算族: BudgetRule → FixedBudgetRule / Rule503020 # 储蓄族: SavingsMethod → FixedAmountMethod / Week52Method / PercentageMethod
鸭子类型依赖对象的方法而非类型
generate_diagnosis()中调用的diagnose()不检查参数具体类型（虽用了类型提示），实际运行时只要传入的对象有diagnose方法即可工作。但项目使用ABC+类型提示提供了编译期和运行期的双重保障。
